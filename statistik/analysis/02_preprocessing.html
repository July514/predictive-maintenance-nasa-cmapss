1. Finale Feature-Auswahl (Ergebnis VIF-Check aus EDA)

Der iterative VIF-Check aus 01_eda.qmd hat vier Sensoren als multikollinear identifiziert und entfernt. Der VIF (Variance Inflation Factor) misst wie stark ein Sensor durch eine Kombination aller anderen vorhergesagt werden kann – Faustregel: VIF > 10 = problematisch.

Sensor VIF Redundant mit Korrelation
sensor_12 52.7 sensor_7 r = 0.99
sensor_7 17.9 sensor_12 r = 0.99
sensor_9 14.9 sensor_14 r = 0.95
sensor_13 14.7 sensor_8 r = 0.96

Der Prozess war iterativ: immer nur den Sensor mit dem höchsten VIF entfernen, dann neu berechnen. Mehrere auf einmal entfernen kann zu falschen Entscheidungen führen, weil Sensoren sich gegenseitig beeinflussen.

2. Rolling Statistics (Rauschunterdrückung)

Warum Rolling Statistics?

Die Rohdaten sind verrauscht – einzelne Zyklen schwanken stark um den eigentlichen Trend, ohne dass das echte Degradation wäre. Ein Modell das auf Rohdaten trainiert wird, lernt auch dieses Rauschen mit.

Wir berechnen für jeden der 12 finalen Sensoren:

  • Gleitender Mittelwert (window = 5): Glättet kurzfristiges Rauschen, macht den Degradationstrend stabiler sichtbar
  • Gleitende Standardabweichung (window = 5): Misst lokale Volatilität – steigt bei fortschreitender Degradation oft an, auch wenn der Mittelwert noch konstant wirkt. Damit ein eigenes informatives Signal.

Das Fenster von 5 Zyklen ist ein Kompromiss: groß genug um Rauschen zu glätten, klein genug um schnelle Degradation am Ende der Lebensdauer nicht zu verschmieren.

Code 
rolling_features <- function(df, sensors, window = 5) {
  df %>%
    group_by(unit_number) %>%
    arrange(time_in_cycles) %>%
    mutate(
      across(
        all_of(sensors),
        list(
          roll_mean = ~ zoo::rollmean(.x, k = window, fill = NA, align = "right"),
          roll_sd   = ~ zoo::rollapply(.x, width = window, FUN = sd, fill = NA, align = "right")
        ),
        .names = "{.col}_{.fn}"
      )
    ) %>%
    ungroup()
}

3. Normalisierung

ML-Modelle, besonders SVR, reagieren sensitiv auf unterschiedliche Skalierungen. Sensor_17 bewegt sich beispielsweise im Bereich 388–400, sensor_6 nur zwischen 21.60 und 21.61. Ohne Normalisierung interpretiert der Algorithmus größere Zahlen als wichtiger – obwohl es nur eine Frage der Einheit ist.

Min-Max-Normalisierung skaliert alle Features auf [0,1], sodass nur die relative Veränderung zählt, nicht die absolute Größe.

Wichtig: Normalisierungsparameter werden ausschließlich aus den Trainingsdaten berechnet und dann auf die Testdaten angewendet. Würde man die Testdaten einbeziehen, wüsste das Modell beim Training implizit etwas über die Test-Verteilung – das wäre Data Leakage und würde die Evaluation verfälschen.

Code 
# Normalisierungs-Parameter aus Training berechnen
feature_cols <- c(final_sensors,
                  paste0(final_sensors, "_roll_mean"),
                  paste0(final_sensors, "_roll_sd"))

norm_params <- train_rolled %>%
  summarise(across(all_of(feature_cols),
                   list(min = ~min(.x, na.rm = TRUE),
                        max = ~max(.x, na.rm = TRUE)),
                   .names = "{.col}__{.fn}")) %>%
  pivot_longer(everything(),
               names_to  = c("feature", "stat"),
               names_sep = "__") %>%
  pivot_wider(names_from = stat, values_from = value)

# Normalisierungsfunktion
normalize_features <- function(df, params) {
  for (feat in params$feature) {
    if (feat %in% names(df)) {
      min_val <- params$min[params$feature == feat]
      max_val <- params$max[params$feature == feat]
      range   <- max_val - min_val
      if (range > 0) {
        df[[paste0(feat, "_norm")]] <- (df[[feat]] - min_val) / range
      } else {
        df[[paste0(feat, "_norm")]] <- 0
      }
    }
  }
  df
}

train_norm <- normalize_features(train_rolled, norm_params)
test_norm  <- normalize_features(test_rolled,  norm_params)

feature_metadata.json

Diese Datei dokumentiert alle Preprocessing-Entscheidungen und -Parameter. Python liest sie beim Laden der Daten, damit Training und Inference exakt dieselbe Pipeline reproduzieren können – insbesondere die Normalisierungsparameter (Min/Max aus dem Training).

Code 
metadata <- list(
  dataset      = "NASA CMAPSS FD003",
  created      = format(Sys.time(), "%Y-%m-%d %H:%M:%S"),
  r_version    = R.version$version.string,

  # Feature-Auswahl
  final_sensors = final_sensors,
  dropped_sensors = list(
    list(sensor = "sensor_12", reason = "VIF 52.7, redundant mit sensor_7 (r=0.99)"),
    list(sensor = "sensor_7",  reason = "VIF 17.9, redundant mit sensor_12"),
    list(sensor = "sensor_9",  reason = "VIF 14.9, redundant mit sensor_14 (r=0.95)"),
    list(sensor = "sensor_13", reason = "VIF 14.7, redundant mit sensor_8 (r=0.96)")
  ),
  constant_sensors = c("sensor_1", "sensor_5", "sensor_16", "sensor_18", "sensor_19"),

  # Rolling Window Parameter
  rolling_window = 5,
  rolling_features = list(
    mean = paste0(final_sensors, "_roll_mean"),
    sd   = paste0(final_sensors, "_roll_sd")
  ),

  # Normalisierungs-Parameter (Min-Max aus Training)
  normalization = list(
    method = "min-max",
    fitted_on = "train",
    params = norm_params
  ),

  # RUL-Kappung
  rul_cap = 125,
  rul_method = "piecewise_linear",

  # Spalten-Dokumentation
  target_col     = "RUL",
  id_cols        = c("unit_number", "time_in_cycles"),
  feature_groups = list(
    raw_sensors     = final_sensors,
    rolling_mean    = paste0(final_sensors, "_roll_mean"),
    rolling_sd      = paste0(final_sensors, "_roll_sd"),
    normalized      = paste0(feature_cols, "_norm")
  )
)

write_json(metadata, "../data/processed/feature_metadata.json",
           pretty = TRUE, auto_unbox = TRUE)
